## Goal
Создать первую рабочую версию Tendura: личного приложения, которое получает тренировки из Training Endurance, показывает их через Telegram-бота, присылает ежедневное уведомление и позволяет после подтверждения записать отчёт спортсмена в выбранную тренировку.

## Scope
- Выделить независимое ядро Tendura и Telegram-бота как первую витрину проекта.
- Получать через внутренний GraphQL API Training Endurance тренировки на сегодня, завтра и неделю.
- Показывать основные данные тренировки: название, дату, описание, тип, длительность, дистанцию, зоны, шаги и повторы, если они присутствуют.
- Реализовать команды `/today`, `/tomorrow` и `/week`.
- Отправлять ежедневную подборку по часовому поясу `Europe/Moscow`.
- Работать через Telegram long polling без обязательного публичного HTTPS-адреса.
- Разрешать доступ только заранее настроенному Telegram-пользователю или чату.
- Поддержать добавление и изменение `postActivityComment` через мутацию `calendarItemUpdateWorkout`.
- При нескольких тренировках запрашивать выбор конкретной тренировки.
- Перед записью показывать предварительный просмотр и требовать явного подтверждения.
- Предупреждать о перезаписи существующего комментария и о том, что отчёт может быть виден тренеру.
- Описать локальный запуск, первоначальную авторизацию и восстановление истёкшей сессии.
- Покрыть тестами преобразование данных, форматирование сообщений и пользовательские сценарии записи отчёта.

## Out of Scope
- Веб-интерфейс, мобильное приложение и другие витрины Tendura.
- Поддержка нескольких пользователей и самостоятельная регистрация в боте.
- Использование официального MCP Training Endurance: для аккаунта спортсмена без PRO он недоступен.
- Парсинг HTML и автоматизация браузера при штатной работе приложения.
- Автоматический ввод или хранение пароля Google либо Training Endurance.
- Редактирование плана тренировки, показателей выполнения и других данных помимо `postActivityComment`.
- Переход на Telegram webhook и полноценное промышленное развёртывание.

## Context
- Проект называется Tendura; название рассчитано на будущее ядро и несколько витрин (`Tendura Core`, `Tendura Bot`, позднее `Tendura Web`).
- Аккаунт Training Endurance бесплатный, вход выполняется через Google.
- Read-only проверка в исходном сеансе подтвердила доступ бесплатного аккаунта к календарю и подробным данным тренировок.
- Веб-клиент обращается к `https://app.trainingendurance.com/graphql`.
- Для чтения обнаружены операции `calendarOverview` и `calendarItems`.
- Для отчёта спортсмена используется поле `Workout.postActivityComment` и мутация `calendarItemUpdateWorkout`.
- Клиент Training Endurance умеет отправлять только изменённое поле комментария без перезаписи всей тренировки.
- Наличие долгоживущей сессии предполагается поведением приложения, но безопасный способ её первоначального получения и обновления нужно подтвердить прототипом.
- В исходном исследовании тестовая запись комментария не выполнялась, поэтому контракт записи требуется окончательно подтвердить только на заранее согласованной тренировке и тексте.
- Внутренний GraphQL API официально не документирован и может измениться.
- Связанные модули: будущие `core`, клиент Training Endurance, Telegram-витрина, планировщик уведомлений, конфигурация.
- Связанные файлы: будут определены после создания каркаса проекта.
- Ограничения: не хранить секреты в репозитории, логах и диагностических ответах; не выполнять запись во внешний сервис без подтверждения пользователя.
- Локально доступны CPython 3.11.3, 3.13.9 и 3.14.x, `pyenv` и `uv 0.11.25`; каркас закреплён на CPython 3.13.9.

## Proposed Architecture
```text
Training Endurance GraphQL
        │ сессия Training Endurance
        ▼
Клиент Training Endurance
        │ нормализованные тренировки
        ▼
Tendura Core
        ├── выбор периода и тренировки
        ├── форматирование данных
        ├── подготовка/подтверждение отчёта
        └── расписание уведомлений
        ▼
Tendura Bot (Telegram long polling)
```

Границы компонентов:

- Клиент Training Endurance отвечает только за авторизацию и GraphQL-контракты.
- Ядро не зависит от Telegram и оперирует собственными моделями тренировок.
- Telegram-витрина преобразует команды и нажатия кнопок в вызовы ядра.
- Планировщик инициирует тот же сценарий получения тренировок, что и команда `/today`.
- Секреты и пользовательские идентификаторы поступают из окружения или локального защищённого хранилища, не из кода.

## Acceptance Criteria
- Авторизованный пользователь получает корректные тренировки командами `/today`, `/tomorrow` и `/week`.
- Посторонний Telegram-пользователь не может читать тренировки или изменять комментарии.
- Ежедневное сообщение отправляется один раз в заданное время по Москве.
- Бот корректно показывает отсутствие тренировок и объясняет необходимость повторной авторизации при истёкшей сессии.
- Пользователь может выбрать тренировку, подготовить отчёт, проверить текст, подтвердить либо отменить запись.
- Существующий отчёт не перезаписывается без отдельного предупреждения и подтверждения.
- После записи приложение проверяет сохранённый `postActivityComment` повторным чтением.
- Секреты отсутствуют в репозитории и логах.
- Основные сценарии покрыты автоматическими тестами; инструкция позволяет запустить проект с чистого окружения.

## Risks
- Внутренний GraphQL API может измениться без предупреждения. Изоляция клиента и контрактные тесты должны локализовать поломку.
- Сессия Training Endurance может иметь меньший срок жизни, чем ожидается. MVP должен явно сообщать о необходимости повторной авторизации.
- Мутация комментария пока подтверждена анализом клиента, но не фактической записью. До проверки функция записи считается экспериментальной.
- Telegram-сообщения имеют ограничения длины и форматирования; недельную выдачу может потребоваться разбивать на несколько сообщений.
- Перезапуск планировщика может привести к повторному уведомлению без небольшого локального хранилища состояния.

## Decisions
- Название проекта: `Tendura`.
- Telegram-бот является первой витриной, а бизнес-логика должна оставаться независимой от Telegram.
- Для MVP используется Python-приложение и Telegram long polling.
- Источник данных бесплатного аккаунта — внутренний GraphQL API Training Endurance; официальный MCP не используется.
- HTML-парсинг и штатная браузерная автоматизация не применяются.
- Часовой пояс по умолчанию — `Europe/Moscow`.
- Запись отчёта выполняется только после предварительного просмотра и явного подтверждения.
- Любая реальная тестовая запись во внешний сервис требует отдельного согласования пользователя.
- Базовая версия проекта — CPython 3.13: она уже установлена локально и поддерживается выбранными инструментами.
- Управление проектом и lock-файлом — через `uv`.
- Предлагаемый минимальный набор production-зависимостей: `python-telegram-bot[job-queue]>=22.8,<23` для long polling и расписания, `httpx>=0.27,<0.29` как прямая зависимость клиента Training Endurance.
- Для конфигурации, часовых поясов и локального состояния использовать стандартную библиотеку (`os`, `zoneinfo`, `sqlite3`); не добавлять `python-dotenv`, отдельный планировщик, ORM или библиотеку моделей без выявленной необходимости.
- Пользователь согласовал production-зависимости; они устанавливаются только в локальную `.venv`, которая исключена из Git.
