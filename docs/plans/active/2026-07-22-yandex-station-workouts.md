## Goal
Добавить к Tendura голосовой интерфейс Яндекс Станции для чтения сегодняшней тренировки, всех тренировок текущей календарной недели и оставшихся тренировок текущей недели, сохранив Telegram и Алису как независимые входные адаптеры над общим application-ядром.

## Scope
- Вынести чтение тренировок из Telegram-обработчиков в переиспользуемый application use case без изменения текущего поведения Telegram.
- Добавить inbound-адаптер навыка Алисы общего типа с HTTPS webhook.
- Поддержать три пользовательских запроса:
  - «Алиса, какая сегодня тренировка»;
  - «Алиса, какие тренировки на этой неделе»;
  - «Алиса, какие ещё тренировки на этой неделе».
- Для «на этой неделе» возвращать понедельник–воскресенье текущей календарной недели.
- Для «какие ещё тренировки» возвращать диапазон от сегодняшнего дня по воскресенье включительно; прошедшие дни не возвращать.
- Формировать короткий голосовой ответ для отсутствующей, одной и нескольких тренировок.
- Ограничить доступ приватным навыком и allowlist владельца.
- Развернуть и проверить навык на реальной Яндекс Станции после отдельного согласования внешних действий.

## Out of Scope
- Подготовка, редактирование, подтверждение или запись отчёта спортсмена через Алису.
- Чтение COROS через Алису.
- Инициативные уведомления со Станции.
- Публичный и многопользовательский навык, собственный OAuth-сервер и связка аккаунтов.
- Изменение семантики существующей Telegram-команды `/week`, которая продолжает показывать семь дней от текущей даты.
- Имитация Tendura как устройства умного дома ради обхода активационного имени навыка.

## Context
- План-исследование: `docs/plans/active/2026-07-21-yandex-station-interface-research.md`.
- Выбранный вариант: общее application-ядро и два входных адаптера в одном репозитории.
- Текущий Telegram-адаптер: `tendura/telegram/bot.py`; выбор дат и вызов `TrainingEnduranceClient.workouts` пока выполняются прямо в обработчике.
- Доменная модель `Workout` уже не зависит от транспорта: `tendura/core/models.py`.
- Outbound-адаптер Training Endurance уже изолирован: `tendura/training_endurance/client.py`.
- Конфигурация и composition root сейчас ориентированы на единственный Telegram-процесс: `tendura/config.py`, `tendura/__main__.py`.
- Яндекс Диалоги вызывают backend навыка через HTTPS и ожидают полный ответ не дольше 4,5 секунды.
- Навык общего типа гарантированно запускается с активационным именем. Голые фразы вида «Алиса, какая сегодня тренировка» могут быть зарегистрированы как интенты внутри активного навыка, но их прямую маршрутизацию из обычного режима Алисы необходимо отдельно проверить на реальном устройстве.
- Перед добавлением новой production-зависимости, созданием облачного ресурса, публикацией навыка или изменением сервера требуется отдельное подтверждение пользователя.
- Официальные источники: [запуск навыка](https://yandex.ru/dev/dialogs/alice/doc/ru/activation), [формат запроса](https://yandex.ru/dev/dialogs/alice/doc/ru/request), [формат ответа](https://yandex.ru/dev/dialogs/alice/doc/ru/response), [интенты и слоты](https://yandex.ru/dev/dialogs/alice/doc/ru/nlu), [приватный доступ](https://yandex.ru/dev/dialogs/alice/doc/ru/access).

|---|---|---|---|
| Сегодня (`/today`) | Да | Интент `workouts.today`, короткий голосовой presenter | Да |
| Завтра (`/tomorrow`) | Да | Интент `workouts.tomorrow` | Нет |
| Неделя (`/week`) | Да, с адаптацией | Краткое резюме и команды «дальше/подробнее»; не читать длинную Telegram-разметку целиком | Да, без пагинации при допустимой длине ответа |
| Подготовить ручной отчёт (`/comment текст`) | Да | Следующую реплику принять как диктовку, повторить распознанный текст и создать pending-операцию | Нет |
| Подготовить отчёт COROS (`/comment_coros`) | Да, после оптимизации | Предварительная синхронизация/кэш либо фоновая операция из-за лимита 4,5 секунды | Нет |
| Подтвердить (`/confirm`) | Технически да, небезопасно как единственный фактор | `YANDEX.CONFIRM`, точный preview, одноразовый pending ID; в первой версии подтверждение отправлять в Telegram | Нет |
| Отменить (`/cancel`) | Да | `YANDEX.REJECT`, удаление pending-операции | Нет |
| Изменить (`/edit`) | Да | Состояние «ожидается новый текст», повторный preview; учитывать ошибки распознавания речи | Нет |
| Ежедневное уведомление | Нет в том же виде | Навык не инициирует диалог; сохранить Telegram или использовать отдельный штатный механизм напоминаний | Нет |
| Короткие Telegram-алиасы | Не нужны | Голосовые синонимы задаются интентами и грамматиками | Нет |

## Acceptance Scenarios

### Сегодня
- Given локальная дата владельца — 2026-07-22.
- When навык получает интент фразы «Какая сегодня тренировка».
- Then application-ядро запрашивает только 2026-07-22 и Alice-presenter озвучивает тренировку либо сообщает, что её нет.

### Текущая календарная неделя
- Given локальная дата владельца — среда 2026-07-22.
- When навык получает интент фразы «Какие тренировки на этой неделе».
- Then запрашивается диапазон с понедельника 2026-07-20 по воскресенье 2026-07-26 включительно, включая прошедшие дни этой недели.

### Оставшаяся часть недели
- Given локальная дата владельца — среда 2026-07-22.
- When навык получает интент фразы «Какие ещё тренировки на этой неделе».
- Then запрашивается диапазон с 2026-07-22 по 2026-07-26 включительно; 20 и 21 июля в ответ не попадают.
- Given сегодня воскресенье.
- Then диапазон содержит только сегодняшнюю дату и не переходит на следующую неделю.

### Маршрутизация Алисы
- Внутри уже активного навыка все три фразы распознаются как разные интенты.
- С закрытой сессии гарантированно работают однофразовые варианты с активационным именем: «Алиса, спроси у [имя навыка], ...».
- Возможность вызывать ровно три короткие фразы без имени навыка проверяется отдельно; если Алиса не маршрутизирует их стороннему навыку, план фиксирует официальное ограничение и не подменяет интеграцию навыком умного дома.

## Target Architecture

```text
Telegram handlers ─┐
                   ├─> GetWorkouts use case ─> WorkoutReader port
Alice webhook ─────┘                              │
                                                  └─> TrainingEnduranceClient

GetWorkouts result ─> Telegram presenter
                   └> Alice text/TTS presenter
```

- Application-ядро принимает явный диапазон дат, actor и timezone-aware clock, возвращает модели/DTO и типизированные ошибки.
- Telegram сохраняет текущие команды и HTML-presenter; его `/week` передаёт диапазон `today..today+6`.
- Alice intent resolver выбирает один из диапазонов: `today`, `calendar_week`, `remaining_calendar_week`.
- Alice-presenter не использует Telegram HTML, сокращает поля до названия, времени/длительности и ключевого описания, а также формирует отдельные `text` и `tts`.
- Alice webhook проверяет версию протокола, skill ID и allowlist `session.user.user_id`, не принимает произвольные даты из реплики и завершает read-only сессию после ответа.
- Outbound-клиент Training Endurance остаётся единственным местом знания GraphQL-контракта.

## Risks
- Три короткие фразы без активационного имени могут быть обработаны встроенной Алисой и не попасть в сторонний навык; официальный гарантированный синтаксис включает имя навыка.
- Training Endurance может не уложиться в 4,5 секунды с учётом сети Яндекса; понадобится небольшой read-only кэш или заранее прогретый процесс.
- Длинное описание тренировки неудобно слушать и может превысить лимиты TTS; presenter обязан приоритизировать ключевые поля.
- Название навыка и спортивные термины могут распознаваться нестабильно на реальном устройстве.
- Текущая ветка `feature/post-workout-feedback` относится к другой работе; реализацию нельзя начинать в ней без безопасного выделения целевой ветки.

## Decisions
- Использовать вариант «общее application-ядро и два входных адаптера в одном репозитории».
- Первая итерация Алисы строго read-only и использует только Training Endurance.
- «На этой неделе» означает текущую календарную неделю с понедельника по воскресенье; существующий Telegram `/week` остаётся скользящим диапазоном на семь дней.
- «Какие ещё тренировки на этой неделе» означает сегодня–воскресенье включительно; сегодняшний день не исключается.
- Для фраз с «ещё» использовать отдельный более специфичный интент.
- Не использовать API умного дома как фиктивное устройство для обхода активационного имени.
- Приватный навык и allowlist владельца достаточны для первой read-only приёмки; публичная авторизация остаётся отдельной задачей.
- Способ HTTPS-размещения выбирается перед реализацией Alice entrypoint с отдельным согласованием внешних ресурсов и новых production-зависимостей.
